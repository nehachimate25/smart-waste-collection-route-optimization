Graph + Adjacency List

Definition: A set of vertices connected by weighted edges.

Purpose in this project: Represents the depot and waste-bin network. Each vertex is a location (depot or bin); each edge's weight is a distance between two locations. The Add Bins & Route planner weights edges with real ROAD distance from OSRM; this page's demo graph uses Haversine (straight-line) distance for academic illustration only. The road lines drawn on the map come from OSRM, never from this graph.

Example: Depot → Bin A : 2.4 km

Main operations: add_vertex, add_edge, get_neighbors, bfs, is_connected

OperationTimeSpace
add_vertex / add_edgeO(1) averageO(V + E)
get_neighborsO(1) average
bfs / is_connectedO(V + E)

Priority Queue + Min Heap

Definition: A queue where each item has a priority; the highest-priority item is always removed first, backed internally by a binary Min Heap.

Purpose in this project: Manages bins according to waste priority - CRITICAL bins are always collected before LOW ones, regardless of report order.

Example: Bin B → 95% → CRITICAL is popped before Bin D → 30% → LOW

Main operations: push, pop, peek, heapify (bulk build)

OperationTimeSpace
push / popO(log n)O(n)
peekO(1)
heapify (bulk build)O(n)

Queue

Definition: A First-In-First-Out (FIFO) structure.

Purpose in this project: Holds pending collection requests in the order they were reported, before urgency is evaluated.

Example: Front → Bin B → Bin C → Bin A → Bin D ← Rear

Main operations: enqueue, dequeue, front

OperationTimeSpace
enqueue / dequeue / frontO(1)O(n)

Stack

Definition: A Last-In-First-Out (LIFO) structure.

Purpose in this project: Records each stop a vehicle visits, in visit order - enabling "most recently visited" display and undo-the-last-stop behaviour.

Example: pushing Depot → Bin B → Bin C means Bin C is on top and would be popped (undone) first.

Main operations: push, pop, peek

OperationTimeSpace
push / pop / peekO(1)O(n)

Hash Table

Definition: Maps keys to values using a hash function, with collisions handled by separate chaining (each bucket holds a small list of entries).

Purpose in this project: Fast O(1) average lookup of a bin or vehicle by its ID.

Example: BIN001 → Bin object

Main operations: put, get, delete

OperationTime (average)Time (worst case)Space
put / get / deleteO(1)O(n)O(n)

Classes and Objects

Definition: User-defined types that bundle data (attributes) and behaviour (methods) together.

Purpose in this project: Bin, Vehicle, and Route are the object types every other data structure actually stores and operates on - a Graph vertex holds a Bin's data, the Hash Table's values are Bins, the Priority Queue orders Bin-carrying requests.

Example: Bin.update_waste_level() is the only way a bin's priority can change - guaranteeing waste level and priority can never drift out of sync.

Dijkstra's Shortest Path (supporting algorithm, not a data structure)

Why it's needed: answers "what is the shortest path between any two points in the network?" - a separate, optional feature from the Priority-Queue-driven collection order.

Which data structures it uses: our own Graph (to know connections) and MinHeap (to always expand the closest unvisited location next) - the same MinHeap class the Priority Queue is built on.

Time complexity: O((V + E) log V) · Space complexity: O(V)
